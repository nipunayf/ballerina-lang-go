# Prototype shortcuts (don't copy as-is)

- **No `$/cancelRequest` support at all**: `lsp/server.go:dispatchRequest` — the method switch has no cancellation case; requests always run to completion.
- **`defer recover()` as the primary error-handling mechanism**: `lsp/definition.go`, `lsp/references.go`, `lsp/symbols.go`, `lsp/code_action.go`, `lsp/completion.go`, `lsp/diagnostics.go`, `lsp/server.go` — each handler wraps its body in a panic recover that logs and returns nil/empty, instead of surfacing structured errors to the client.
- **No `textDocument/signatureHelp` handler**: not present in `dispatchRequest`'s method switch or anywhere in `lsp/`.
- **Diagnostics debounced via `time.Sleep` in a goroutine**: `lsp/server.go:scheduleDiagnostics` — spawns `go func() { time.Sleep(delay); ... }()` per change rather than a cancellable timer/worker queue; staleness is caught after the fact via `seq`/`updateSeq` guards in `handleDiagnosticJob`/`publishDiagnostics`.
- **No query-result cache — only per-module stage memoization**: `lsp/references.go:runTopoPrefixFrontend` and `lsp/symbols.go:workspaceSymbols` re-drive `runModuleFrontend` synchronously on the request goroutine for every candidate module on every call. `runModuleFrontend` (`lsp/diagnostics.go:109-111`) skips a module's already-completed stages (`if module.Stage >= target { return true }`), so repeated compilation work is avoided, but there is no cached query result (definitions/references/symbols) to reuse — the AST walk and symbol lookup themselves always re-run.
- **Completion: request-time full recompile of target module, ignoring debounced diagnostics work**: `lsp/completion.go:recoveringCompilationUnit` (line 216-222) parses and builds recovering AST on every request. `snapshotWithRecoveredCU` (lines 1119-1156) resets the target module's Stage to FrontendStageNone and clears all frontend-derived state. `runModuleFrontend` then recompiles to FrontendStageLocalTypeResolved (line 267) synchronously on the request goroutine. Meanwhile, `scheduleDiagnostics` spawns a debounced compile (server.go:405), but its results are never used by completion — the target module is always re-parsed fresh. Dependency modules reuse their Stage across snapshots (snapshot.go:186), so runModuleFrontend skips their already-completed stages, but the target module is always rebuilt.
