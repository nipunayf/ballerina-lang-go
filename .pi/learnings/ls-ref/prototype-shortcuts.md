# Prototype shortcuts (don't copy as-is)

## Ticket-08 (legacy) shortcuts — fixed in ticket-09

- **No `$/cancelRequest` support at all**: `lsp/server.go:dispatchRequest` — the method switch has no cancellation case; requests always run to completion. **Fixed in ticket-09**: `ls/ls/server/server.go:handleCancelRequest()` implements `$/cancelRequest` with per-request context cancellation via `requestRegistry`.
- **`defer recover()` as the primary error-handling mechanism**: `lsp/definition.go`, `lsp/references.go`, `lsp/symbols.go`, `lsp/code_action.go`, `lsp/completion.go`, `lsp/diagnostics.go`, `lsp/server.go` — each handler wraps its body in a panic recover that logs and returns nil/empty, instead of surfacing structured errors to the client. **Partially fixed in ticket-09**: `ls/ls/core/compile/compile.go:runCycle()` uses panic-recover for compile failures (publishes CE-E2), but the server layer uses structured error responses.
- **No `textDocument/signatureHelp` handler**: not present in `dispatchRequest`'s method switch or anywhere in `lsp/`.
- **Diagnostics debounced via `time.Sleep` in a goroutine**: `lsp/server.go:scheduleDiagnostics` — spawns `go func() { time.Sleep(delay); ... }()` per change rather than a cancellable timer/worker queue; staleness is caught after the fact via `seq`/`updateSeq` guards in `handleDiagnosticJob`/`publishDiagnostics`. **Fixed in ticket-09**: `ls/ls/core/compile/compile.go:scheduleDebounced()` uses `time.AfterFunc` with per-root timers and generation tracking.
- **No query-result cache — only per-module stage memoization**: `lsp/references.go:runTopoPrefixFrontend` and `lsp/symbols.go:workspaceSymbols` re-drive `runModuleFrontend` synchronously on the request goroutine for every candidate module on every call. `runModuleFrontend` (`lsp/diagnostics.go:109-111`) skips a module's already-completed stages (`if module.Stage >= target { return true }`), so repeated compilation work is avoided, but there is no cached query result (definitions/references/symbols) to reuse — the AST walk and symbol lookup themselves always re-run.
- **Completion: request-time full recompile of target module, ignoring debounced diagnostics work**: `lsp/completion.go:recoveringCompilationUnit` (line 216-222) parses and builds recovering AST on every request. `snapshotWithRecoveredCU` (lines 1119-1156) resets the target module's Stage to FrontendStageNone and clears all frontend-derived state. `runModuleFrontend` then recompiles to FrontendStageLocalTypeResolved (line 267) synchronously on the request goroutine. Meanwhile, `scheduleDiagnostics` spawns a debounced compile (server.go:405), but its results are never used by completion — the target module is always re-parsed fresh. Dependency modules reuse their Stage across snapshots (snapshot.go:186), so runModuleFrontend skips their already-completed stages, but the target module is always rebuilt. **Fixed in ticket-09**: completion uses a non-blocking lease on a pre-compiled stable snapshot's completion index. No recompilation, no snapshot cloning.
- **`snapshotWithRecoveredCU` creates a shallow copy of the entire snapshot**: `lsp/completion.go:1119-1156` — copies all modules (shallow struct copy), deep-copies only the `CompilationUnits` map, then resets the target module's `Stage`, `Imports`, `ImportsResolved`, `ImportedByCU`, `ImportedSymbols`, `Package`, `Exported`, `CFG` to zero values. This is a prototype shortcut — copying the entire snapshot per request is wasteful. A production design should mutate the module in-place or use a lighter-weight overlay. **Fixed in ticket-09**: no snapshot cloning at all for completion.
- **`recoveringCompilationUnit` creates a fresh `NodeBuilder` per request**: `lsp/completion.go:215-222` — calls `ast.NewRecoveringNodeBuilder(cx)` which allocates a new `NodeBuilder` with its own `constantSet`, `typeTable`, `reportedSyntaxDiagnostics` map. The `NodeBuilder` is not cached or reused across requests. `ast/node_builder.go:115-120` — `NewRecoveringNodeBuilder` sets `NodeBuilderModeRecover` which tolerates parse errors (produces `BLangBadStmt`/`BLangBadExprOrAction`/`BLangBadIdentifier` nodes). This is the pattern to replicate for the target's "recovering NodeBuilder construction" — but the allocation cost should be measured; if the `NodeBuilder` is stateless enough, it could be pooled.
- **No snapshot-level locking**: `lsp/snapshot.go:SnapshotManager` — `Current()`/`Publish()` use simple pointer swap with no mutex. The `Server.Run()` loop is single-threaded for request dispatch (one goroutine reads messages, one goroutine processes them sequentially via the `messages` channel). This means no concurrent access to snapshots from request handlers. The target's concurrent design will need proper synchronization that the PoC doesn't model. **Fixed in ticket-09**: `SnapshotStore` uses `sync.Mutex` for all map operations, `SnapshotStore.lease()` uses per-root lease counting with deferred eviction, and the server uses `requestRegistry` with per-request cancellable contexts.

## Completion feature gaps — not implemented in PoC

- **No argument-position completion** (foo(<cursor>)): `lsp/completion.go` has no dedicated invocation/call context handler. Argument positions fall to `completionKindExpression` (line 103) which returns visible variables/functions (300-302), with no filtering by expected argument type.
- **No expected-type-driven ranking**: No query for "what type does this context expect?" No code filters or ranks completion candidates based on whether they match a context's expected type.
- **No signature help handler** (`textDocument/signatureHelp`): not present in `lsp/server.go:dispatchRequest` method switch.

## Ticket-09 remaining shortcuts

- **Compile cancellation is boundary-only**: `ls/ls/core/compile/compile.go:Cancel()` bumps the workspace generation so the running compile's result is gated out at the stale-publication gate (CE-E3). Go cannot interrupt a running compile, so the compile goroutine still runs to completion — only its output is discarded.
- **No per-document request-to-root mapping for cancellation**: `Cancel()` applies to every active root, not a specific document. Per-root identification of the cancelled request is deferred to 10/11.
- **`realCompilePackage` still uses panic-recover for Phase-2 failures**: `ls/ls/core/compile/compile.go:runCycle()` recovers panics from `compileFn` and publishes CE-E2. The compiler re-panics on Phase-2 failures (goroutine panics are re-panicked after `wg.Wait()` in `projects/package_compilation.go:compileModulesInternal()`).
