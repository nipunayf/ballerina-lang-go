## Ticket 33 — scoped environment handle for AST-only completion

- **Status:** type=implement, status=claimed, blocked by=none. `docs/raw/ls-backlog/issues/33-expose-scoped-environment-handle-to-query.md:1-4`
- **Spawned by ticket 32 decision:** ticket 32 decided to move completion's cursor classification to AST-only (`ast.BLangNode`), dropping `tree.*` from that path. Realizing that requires widening the ticket-07 seam — a scoped environment handle exposed from `ls/projects` into `ls/core/query`. `docs/raw/decisions/2026-07-21-completion-reader-writer-strategy.md:Decision §1`
- **Design premise:** `ast.BLangNode` is assumed to carry all position/token/trivia information cursor classification needs — mirroring gopls's single-tree model and ls-ref's existing practice. Any gap is closed in this ticket, not a reason to retain `tree.*`. `docs/raw/decisions/2026-07-21-completion-reader-writer-strategy.md:Design premise`
- **Design questions owned by ticket 33:** (1) Does `ast.BLangNode` already carry the position/token-boundary/trivia info `classifyContext()` reads off `tree.*`, or must the builder be extended? (2) What's the minimal `CompilerEnvironment` surface the query layer needs (symbol spaces / type environment / package interner access for `NodeBuilder`), packaged as a facade that doesn't leak `ls/projects` internals? (3) Where does the handle get constructed/held — per-snapshot (ls-ref's pattern), and how does it plug into `SnapshotStore`/`StableSnapshot` machinery? (4) Does exposing this handle change `CompletionLease`/generation-match behavior, or is it purely additive? (5) Migration path for `classifyContext()` — full replacement or transition period? `docs/raw/ls-backlog/issues/33-expose-scoped-environment-handle-to-query.md:Design questions this ticket owns`
- **ls-ref pattern:** builds a fresh, thin `context.NewCompilerContext(snapshot.Env)` per request, but the expensive shared state (`CompilerEnvironment`) lives on `Snapshot` and carries forward across incremental generations; only the target module's frontend stage resets and rebuilds. `docs/raw/decisions/2026-07-21-completion-reader-writer-strategy.md:Research summary §ls-ref`
- **Current seam:** `ls/core/query` has zero access to `*context.CompilerContext` or `CompilerEnvironment` — that type lives inside `ls/projects`, behind the boundary ticket 07 deliberately drew. `NodeBuilder` needs a `*context.CompilerContext` (`ls/ast/node_builder.go:111-116`), which only exists inside `ls/projects`. `docs/raw/ls-backlog/issues/33-expose-scoped-environment-handle-to-query.md:Question`
- **Ticket 33 is a shared API (new package-boundary-crossing facade):** runs the full `grill-me` interview per the ls-iteration classify table, not the local-handler path. `docs/raw/ls-backlog/issues/33-expose-scoped-environment-handle-to-query.md:Question`
- **Map.md status:** listed under M4 as "unblocked, shared-API tier" — designs the ticket-07 seam-widening that ticket 32's AST-only decision depends on. `docs/raw/ls-backlog/map.md:Not yet specified §M4`
- **Ticket 33 is NOT the cooperative-compile-cancellation follow-up:** that is a separate blocked-on-ADR-018-§2 ticket, not ticket 33. `docs/raw/decisions/2026-07-21-completion-reader-writer-strategy.md:Follow-up tickets`

## Ticket 36 — drop completion's precomputed semantic indexes

- **Status:** type=implement, status=claimed, blocked by=none. `docs/raw/ls-backlog/issues/36-drop-completion-semantic-indexes.md:1-4`
- **Reopens ticket 32's affirmation of precompute/lease/degrade:** ticket 32 affirmed the current design; ticket 36 reopens specifically for the semantic-fact side (cursor classification already AST-only in ticket 33, unaffected). `docs/raw/ls-backlog/issues/36-drop-completion-semantic-indexes.md:Question`
- **Research verdict (per-fact-type):**
  - `CompletionIndex` (module-level declaration facts) — **fully feasible on demand.** Pure syntax-tree walk, no resolver state. `docs/raw/ls-backlog/research/36-drop-completion-semantic-indexes.md:Verdict per index type §CompletionIndex`. Verified: `BuildCompletionIndex` at `projects/completion_index.go:92-131` walks `Package` → `Module` → `Document.SyntaxTree()` → `tree.ModulePart.Members()`, no resolver state. `projects/completion_index.go:92-131`
  - `ImportCatalog` — **feasible in principle, thread-safety gap.** Reads `Environment.publicSymbols` (compile-worker-only, unguarded). Needs `sync.RWMutex` fix. `docs/raw/ls-backlog/research/36-drop-completion-semantic-indexes.md:Verdict per index type §ImportCatalog`
  - `ExpectedTypeIndex`, `MemberCompletionIndex`, `InvocationCompletionIndex` — **infeasible on demand without a compiler change.** All three captured as side effect inside `analyzeAndDesugar`, before desugar destroys the AST/scope state they depend on. No post-compile facade (`SemanticModel()` is a nil stub at `projects/package_compilation.go:230-232`). `docs/raw/ls-backlog/research/36-drop-completion-semantic-indexes.md:Verdict per index type §ExpectedTypeIndex, MemberCompletionIndex, InvocationCompletionIndex`. Verified: index builders called at `projects/module_context.go:356-358` (before desugar at `:407`). `SemanticModel()` returns `nil` at `projects/package_compilation.go:230-232`.
- **Destination architecture (bls-docs/feat3) wants on-demand `SemanticModel` live queries, not precomputed indexes:** ADR-042 §6 routes completion through `StableSnapshot.semanticModel(ModuleId)`; ADR-061 permits `compilation.getSemanticModel(moduleId)`; jBallerina's `SemanticModel.expectedType(Document, LinePosition)` is a live, on-demand query. `docs/raw/ls-backlog/research/36-drop-completion-semantic-indexes.md:explore-ls-docs`
- **Draft design proposal (superseded by HIL-gate):** lease returns `*projects.Package` instead of four structs; `CompletionIndex`/`ImportCatalog` move to on-demand computation; the other three regress. `docs/raw/ls-backlog/design/36-drop-completion-semantic-indexes.md:Proposal`
- **HIL-approved design (SkipDesugaring approach):** new `SkipDesugaring` compilation option gates `desugar.DesugarPackage(...)` at `projects/module_context.go:407` for LS compiles only; CLI codegen path leaves it unset. With desugar skipped, all five index types relocate to on-demand reads of `lease.Package()`. No index struct of any kind survives. `docs/raw/ls-backlog/design/36-drop-completion-semantic-indexes.md:Per-fact-type disposition §3`
- **Risk called out explicitly:** real behavioral regression for member-access/invocation/expected-type completion — ships only if HIL gate accepts that tradeoff. `docs/raw/ls-backlog/design/36-drop-completion-semantic-indexes.md:Risk called out explicitly`. Also: skipping desugar for LS compiles creates a real pipeline divergence (LS: resolve/typecheck only; CLI: resolve/typecheck + desugar + BIR gen). `docs/raw/ls-backlog/design/36-drop-completion-semantic-indexes.md:Risk called out explicitly`
- **Shared API (reshapes `CompletionLease` interface and `compile`/`query` package boundary):** runs full `grill-me` interview. `docs/raw/ls-backlog/issues/36-drop-completion-semantic-indexes.md:Question`
- **Current `CompletionLease` interface** exposes five methods: `Index()`, `ExpectedTypeIndex()`, `ImportCatalog()`, `MemberCompletionIndex()`, `InvocationCompletionIndex()`. `ls/core/query/completion.go:30-35`, `ls/core/compile/compile.go:506-560`. Verified: `ls/ls/core/query/completion.go:30-35` (interface), `ls/ls/core/compile/compile.go:506-560` (implementation struct with five fields + `Lease()` factory).
