# Semantic queries / completion

- **Completion reads SemanticModel on-demand from StableSnapshot:** ADR-042 §6 routes completion to `StableSnapshot` (stale OK, latency beats freshness), and ADR-061 + task T-028 confirm the steady-state read path is `StableSnapshot.semanticModel(moduleId)` calling `compilation.getSemanticModel(moduleId)` directly — no precomputed projections. `architecture/adrs/ADR-042-dual-snapshot-access-pattern.md:§6`, `architecture/adrs/ADR-061-compiler-sdk-access-boundary.md:§Decision`, `tasks/task_T-028.md:§Constraints`
- **Hover/go-to-def use InProgressSnapshot:** ADR-042 §6 — stale navigation target is a correctness failure. `architecture/adrs/ADR-042-dual-snapshot-access-pattern.md:§6`
- **Two-tier readiness (Syntax vs Semantic):** ADR-020 §1 classifies completion, hover, definition, references, semanticTokens, diagnostics as SEMANTIC tier requiring full ProjectSnapshot. Syntax tier (documentSymbol, foldingRange, etc.) served from SyntaxTree only. `architecture/adrs/ADR-020-progressive-startup-strategy.md:§1`
- **Stale-result serving for semantic requests:** ADR-020 §2 — if StableSnapshot exists (even stale by ≤1 edit), return it immediately with staleness annotation. If no snapshot (cold start), return ContentModified error with retryAfterMs. `architecture/adrs/ADR-020-progressive-startup-strategy.md:§2`
- **Generic LSP Handler Registry for completions:** ADR-029 mandates `LanguageFeatureProvider` SPI with `getCompletions(CompletionContext)`. Core LS completions + plugin completions merged. `architecture/adrs/ADR-029-generic-lsp-handler-registry.md:§1-3`
- **Completion on request thread reads DualSnapshotStore:** ADR-058 + async-compilation-pipeline.feature — request threads never run compilation; they read stable snapshots from central bounded store. `architecture/adrs/ADR-058-central-dual-snapshot-store.md`
- **50 concurrent hover/completion requests must not crash:** QA-1 scenario — 0 concurrent modification crashes, 0 deadlocks. `architecture/quality-attribute-scenarios.md:QA-1`
- **Hover/completion respond within 200ms:** QA-6 scenario — even during background compilation. `architecture/quality-attribute-scenarios.md:QA-6`
- **Persistent symbol index for cold-start completion:** ADR-020 §4 — serialized public declarations (function signatures, type names, module exports) to disk for warm-start hover/completion before first full compilation. `architecture/adrs/ADR-020-progressive-startup-strategy.md:§4`
- **Completion feature routing via facade:** LG-C3 (RequestSemanticFeature) — facade resolves Path/URI to project/module, may call CompilerCompilationGuard on already-owned compiler SDK objects, or read stable snapshot through CompilationService. `architecture/domain-model/commands.md:LG-C3`
- **Expected-type projections deferred from semantic query surface:** ticket 12 decision explicitly says "Expected-type/context, and invocation/signature facts are added with their own feature work" — they were always planned as a separate addition after the initial semantic query surface. `docs/raw/decisions/2026-07-15-semantic-query-surface.md:Decision §3`
- **Expected-type ranking deferred from completion vertical slice:** ticket 14 decision explicitly defers "expected-type ranking" as out of scope for the non-blocking slice. `docs/raw/decisions/2026-07-16-completion-vertical-slice.md:Consequences`
- **Snapshot eviction safe during concurrent semantic reads:** implementation-alignment-hardening.feature — eviction callback must not run domain logic beyond cleanup coordination. `architecture/scenarios/implementation-alignment-hardening.feature:Scenario`
- **The compiler has no `ExpectedType` query for LS use** — `setExpectedType` is a compiler-internal function that stores the expected type on AST nodes during type resolution, not a query API. `semantics/type_resolver.go`, `semantics/semantic_analyzer.go`
- **jBallerina's `SemanticModel` does expose `expectedType(Document, LinePosition)` returning `Optional<TypeSymbol>`** — this is the jBallerina API that the Go interpreter's LS would need to replicate. `bls-docs/feat3/architecture/inputs/dependencies/ballerina-lang.md:26`
- **Cost/performance: Active projects read SemanticModel on-demand; background projects evict it to memory-bounded symbol-index:** ADR-013 §5 mandates active/background tier classification — active projects (openDocuments ≠ ∅) retain full `SemanticModel` in memory and read on-demand; background projects evict full `SemanticModel` and keep only surface-level symbol index (public declarations). No steady-state precomputed projection layer. `architecture/adrs/ADR-013-bounded-memory-eviction.md:§5 (lines 72-74)`

## Ticket 36 — drop precomputed semantic indexes, derive from compiled package

- **Ticket 36 reopens ticket 32's affirmation of precompute/lease/degrade** specifically for the semantic-fact side. `docs/raw/ls-backlog/issues/36-drop-completion-semantic-indexes.md:Question`
- **Research verdict:** `CompletionIndex` (module-level declarations) is fully feasible on demand (pure syntax walk); `ImportCatalog` is feasible with a `sync.RWMutex` fix on `Environment.publicSymbols`; `ExpectedTypeIndex`, `MemberCompletionIndex`, `InvocationCompletionIndex` are infeasible on demand without a compiler change — all three are captured as side effects inside `analyzeAndDesugar` before desugar destroys the AST/scope state. `docs/raw/ls-backlog/research/36-drop-completion-semantic-indexes.md:Verdict per index type`
- **Destination architecture (bls-docs/feat3) wants on-demand `SemanticModel` live queries, not precomputed indexes:** ADR-042 §6 routes completion through `StableSnapshot.semanticModel(ModuleId)`; ADR-061 permits `compilation.getSemanticModel(moduleId)`; jBallerina's `SemanticModel.expectedType(Document, LinePosition)` is a live, on-demand query. `docs/raw/ls-backlog/research/36-drop-completion-semantic-indexes.md:explore-ls-docs`
- **Draft design proposes:** lease returns `*projects.Package`; `CompletionIndex`/`ImportCatalog` move to on-demand; the other three regress (fall back to declaration/scope-level only). `docs/raw/ls-backlog/design/36-drop-completion-semantic-indexes.md:Proposal`
- **HIL-approved design (SkipDesugaring approach):** new `SkipDesugaring` compilation option gates `desugar.DesugarPackage(...)` at `projects/module_context.go:407` for LS compiles only. With desugar skipped, all five index types relocate to on-demand reads of `lease.Package()`. No index struct survives. `docs/raw/ls-backlog/design/36-drop-completion-semantic-indexes.md:Per-fact-type disposition §3`
- **Risk:** real behavioral regression for three named completion kinds — ships only if HIL gate accepts that tradeoff. Also: LS/CLI pipeline divergence (LS skips desugar, CLI doesn't). `docs/raw/ls-backlog/design/36-drop-completion-semantic-indexes.md:Risk called out explicitly`
- **Verified code pointers:** `BuildCompletionIndex` at `projects/completion_index.go:92-131` (pure syntax walk). Index builders called at `projects/module_context.go:356-358` (before desugar at `:407`). `SemanticModel()` returns `nil` at `projects/package_compilation.go:230-232`. `CompletionLease` interface at `ls/ls/core/query/completion.go:30-35`; implementation at `ls/ls/core/compile/compile.go:506-560`.

## AST-only cursor classification (ticket 32/33)

- **Ticket 32 decided to move completion's cursor classification to AST-only** (`ast.BLangNode`), dropping `tree.*` from that path. `docs/raw/decisions/2026-07-21-completion-reader-writer-strategy.md:Decision §1`
- **Design premise:** `ast.BLangNode` is treated as carrying all the position/token/trivia information cursor classification needs — mirroring gopls's single-tree model (`go/ast` carries sufficient position/comment fidelity without a separate CST) and matching ls-ref's existing practice. This is deliberately not rust-analyzer's pattern (which keeps its rowan CST exposed to completion because its HIR layer doesn't carry that fidelity). `docs/raw/decisions/2026-07-21-completion-reader-writer-strategy.md:Design premise`
- **Current `classifyContext()` uses `tree.*`:** `ls/core/query/completion_module.go:91-140` — walks `tree.ModulePart`, `tree.FunctionDefinition`, `tree.ImportDeclarationNode`, etc. for cursor classification. `ls/core/query/completion_module.go:91`
- **`ast.BLangNode` lacks `Parent()`/`Ancestor()`/`TextRange()` facade** that completion's current `classifyContext()` uses. `docs/raw/ls-backlog/research/32-rearchitect-completion-reader-writer-strategy.md:Per-source findings §This repo's compiler`
- **ls-ref proves AST-only classification works:** `completion.go:222` has the one `tree.*` touch (`builder.TransformModulePart(...)`); everything downstream — `nodeChainAtOffset` (`:886`, `ast.Walk` over `ast.BLangNode`), `completionContextFromNodeChain` (`:552`) — walks the semantic AST exclusively. Prefix scanning is plain string/byte-offset work touching neither tree.* nor ast.*. `docs/raw/ls-backlog/research/32-rearchitect-completion-reader-writer-strategy.md:Per-source findings §ls-ref PoC`
- **Ticket 33 owns closing any gap** between the design premise and `ast.BLangNode`'s actual fidelity. `docs/raw/ls-backlog/issues/33-expose-scoped-environment-handle-to-query.md:Design premise`
