# Compiler APIs

- **BallerinaCompilerApi for loading/discovery only:** ADR-061 narrows ADR-045 — project loading, workspace discovery, compiler environment entry points go through BallerinaCompilerApi. Owned-object navigation (Project, Package, Module, Document, PackageCompilation, SemanticModel, SyntaxTree) may be direct inside WM and CE. `architecture/adrs/ADR-061-compiler-sdk-access-boundary.md`
- **No direct compiler SDK calls outside WM/CE:** ADR-061 — LSP Gateway must not perform compiler orchestration; receives results through service methods and compatibility facade. `architecture/adrs/ADR-061-compiler-sdk-access-boundary.md:Consequences`
- **No BuildOptions.setSticky(true):** ADR-061 — new code must use explicit LockingMode semantics. `architecture/adrs/ADR-061-compiler-sdk-access-boundary.md:Decision`
- **Resolution-first pipeline:** ADR-049 — CE calls pkg.getResolution() first. If resolution fails with qualifying errors → recovery ladder. If non-qualifying → CE-E4 (no compilation). If clean → pkg.getCompilation() + pkg.getBuildToolResolution() → CE-E5. `architecture/adrs/ADR-049-resolution-first-pipeline-recovery-ladder.md`
- **CE-E5a/CE-E5b mutual exclusivity:** ADR-060 — resolution diagnostics and compilation diagnostics are mutually exclusive per compilation cycle. `architecture/adrs/ADR-060-compilation-event-taxonomy.md`
- **DualSnapshotStore central bounded store:** ADR-058 — 16 stable snapshots default, LRU eviction, eviction listener for WM cleanup. Lock-free stable reads. `architecture/adrs/ADR-058-central-dual-snapshot-store.md`
- **Compiler API immutability guarantee:** ADR-042 §Context — document.modify().withContent().apply() creates new Document/Module/Package objects; old objects unchanged. Structural sharing free. `architecture/adrs/ADR-042-dual-snapshot-access-pattern.md:Context`
- **Cancellation via thread interrupt:** ADR-018 — no compiler API cooperative cancellation hooks available yet. Thread interrupt is safe because compiler is side-effect-free. Phase-boundary checkpoints are future work. `architecture/adrs/ADR-018-cooperative-cancellation-model.md:Mandate 8`
- **CompilationService API:** api-contracts.md — exposes stableSnapshot(Project, PackageDescriptor, CancelChecker) and latestSnapshot(Project, PackageDescriptor, CancelChecker). No Path-based syntax-tree/semantic-model methods. `architecture/structural/api-contracts.md:CompilationService`

## Ticket 36 — dropping precomputed indexes changes the seam

- **Ticket 36 proposes changing `CompletionLease` to return `*projects.Package`** instead of four precomputed structs. `docs/raw/ls-backlog/design/36-drop-completion-semantic-indexes.md:Proposal`
- **`ls/core/query` would gain a bounded, read-oriented dependency on `*projects.Package`** (already partially true — `query.go`'s `DocumentSymbols` already reads `project.CurrentPackage()` directly). No new dependency on `ls/core/compile` — the lease interface (`CompletionLeaser`) stays the abstraction boundary. `docs/raw/ls-backlog/design/36-drop-completion-semantic-indexes.md:What this depends on`
- **`Environment.publicSymbols` needs a `sync.RWMutex`** (small, scoped compiler-side change) to make `ImportCatalog` recomputable on demand from request goroutines. `docs/raw/ls-backlog/design/36-drop-completion-semantic-indexes.md:Per-fact-type disposition §2`
- **The three resolver-capture indexes (`ExpectedTypeIndex`, `MemberCompletionIndex`, `InvocationCompletionIndex`) cannot be served on demand** under this compiler today — they depend on pre-desugar state that doesn't survive post-compile. `docs/raw/ls-backlog/research/36-drop-completion-semantic-indexes.md:Verdict per index type`
- **HIL-approved SkipDesugaring approach:** new `SkipDesugaring` compilation option gates `desugar.DesugarPackage(...)` at `projects/module_context.go:407` for LS compiles only. With desugar skipped, all five index types relocate to on-demand reads of `lease.Package()`. No index struct survives. `docs/raw/ls-backlog/design/36-drop-completion-semantic-indexes.md:Per-fact-type disposition §3`
- **This is a shared API (reshapes the `CompletionLease` interface and its `compile`/`query` package boundary):** runs the full `grill-me` interview. `docs/raw/ls-backlog/issues/36-drop-completion-semantic-indexes.md:Question`
- **Verified code pointers:** `CompletionLease` interface at `ls/ls/core/query/completion.go:30-35` (five methods). Implementation struct at `ls/ls/core/compile/compile.go:506-560` (five fields + `Lease()` factory). `BuildCompletionIndex` at `projects/completion_index.go:92-131` (pure syntax walk). Index builders called at `projects/module_context.go:356-358` (before desugar at `:407`). `SemanticModel()` returns `nil` at `projects/package_compilation.go:230-232`.

## Environment handle seam (ticket 33)

- **Current seam:** `ls/core/query` has zero access to `*context.CompilerContext` or `CompilerEnvironment` — that type lives inside `ls/projects`, behind the boundary ticket 07 deliberately drew. `docs/raw/ls-backlog/issues/33-expose-scoped-environment-handle-to-query.md:Question`
- **NodeBuilder dependency:** `NodeBuilder` needs a `*context.CompilerContext` (`ls/ast/node_builder.go:111-116`), which only exists inside `ls/projects`. Zero references to `CompilerContext` construction exist in `ls/core/query/` or `ls/server/`. `docs/raw/ls-backlog/research/32-rearchitect-completion-reader-writer-strategy.md:Per-source findings §This repo's compiler`
- **Ticket 32 decision requires widening the seam:** completion's cursor classification moves to AST-only (`ast.BLangNode`), dropping `tree.*`. Realizing that requires a scoped, read-oriented environment handle exposed from `ls/projects` into `ls/core/query`, sized to support cheap per-request `NodeBuilder`/`NewRecoveringNodeBuilder` construction without giving the query layer general compiler-environment access (project loading, mutation, etc.). `docs/raw/decisions/2026-07-21-completion-reader-writer-strategy.md:Decision §1`
- **ls-ref pattern for the handle:** builds a fresh, thin `context.NewCompilerContext(snapshot.Env)` per request, but the expensive shared state (`CompilerEnvironment`) lives on `Snapshot` and carries forward across incremental generations; only the target module's frontend stage resets and rebuilds. `docs/raw/decisions/2026-07-21-completion-reader-writer-strategy.md:Research summary §ls-ref`
- **Minimal surface needed:** symbol spaces / type environment / package interner access for `NodeBuilder` — packaged as a facade that doesn't leak the rest of `ls/projects`'s internals. `docs/raw/ls-backlog/issues/33-expose-scoped-environment-handle-to-query.md:Design questions this ticket owns §2`
- **Per-snapshot construction:** the handle is constructed per-snapshot (ls-ref's pattern), plugged into `SnapshotStore`/`StableSnapshot` machinery (ticket 09). `docs/raw/ls-backlog/issues/33-expose-scoped-environment-handle-to-query.md:Design questions this ticket owns §3`
- **Orthogonal to CompletionLease:** exposing the handle is purely additive — a new input to cursor classification, orthogonal to the existing semantic-fact lease. `docs/raw/ls-backlog/issues/33-expose-scoped-environment-handle-to-query.md:Design questions this ticket owns §4`
- **Ticket 33 is a shared API (new package-boundary-crossing facade):** runs the full `grill-me` interview per the ls-iteration classify table. `docs/raw/ls-backlog/issues/33-expose-scoped-environment-handle-to-query.md:Question`
